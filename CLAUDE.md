# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal portfolio for Mehdi Aichouch, live at https://www.mehdiaichouch.com: a single-page Create React App site (React 18, Tailwind CSS 3) with no router and no backend, prerendered to static HTML at build time (English at `/`, French at `/fr`).

## Commands

```bash
npm start                                          # dev server on http://localhost:3000
CI=false npm run build                             # production build to build/, then scripts/seo/prerender.js (CI=false stops lint warnings from failing the build)
CI=true npx react-scripts test --watchAll=false    # run all tests once
CI=true npx react-scripts test --watchAll=false -t "Language switcher"   # run one describe/test by name
```

Linting is CRA's built-in ESLint (`react-app` config), which runs during `start` and `build`. There is no separate lint script.

To build, serve, and visually verify the site at different viewport sizes, use the project skill `.claude/skills/verify/SKILL.md`.

## Environment

Copy `.env.example` to `.env`. Every variable needs the `REACT_APP_` prefix and is inlined into the client bundle at build time:
- `REACT_APP_EMAILJS_*`: used by the contact form (`src/services/contactService.js`, sent through EmailJS).
- `REACT_APP_OPENROUTER_API_KEY`: used by the AI chat assistant (`src/services/chatService.js`).
- Optional: `REACT_APP_GA_MEASUREMENT_ID` turns on cookieless Google Analytics (`src/lib/analytics.js`, off when empty); `REACT_APP_GOOGLE_SITE_VERIFICATION` / `REACT_APP_BING_SITE_VERIFICATION` add the verification meta tags.

## Architecture

- **Page layout:** `src/App.jsx` stacks the sections (`Home`, `About`, `Portfolio`, `Skills`, `Experience`, `Contact`) inside `LazyMotion`, `MotionConfig`, `LanguageProvider` and `ResumeModalProvider`. In production the HTML is prerendered and `src/index.js` hydrates it (`<App prerendered />`): every section is in the first render to match the HTML, each in its own `Suspense` boundary so React hydrates them one at a time after the hero (keeps Total Blocking Time down). On the dev server and in tests `#root` is empty: only the hero renders in the first pass, everything below the fold mounts right after inside `startTransition`, and a `#hash` deep link is re-applied once it has. Each section is a `<section id=…>`; navigation is plain `<a href="#id">` anchors, with CSS `scroll-behavior: smooth` and `scroll-padding-top: var(--nav-h)` doing the smoothing and header offset. The order and the `01`…`05` micro-label numbers come from `src/data/navLinks.js`, labels from `nav.*` translations. The desktop nav shows from `lg` (1024px) up because the French labels don't fit at `md`.
- **i18n (EN/FR):** `src/context/LanguageContext.jsx` provides `t("dotted.key")`, which looks up `src/i18n/translations.js` and returns the key itself when nothing matches. The URL decides the language: `/` is English, `/fr` is French (`langFromPath` in `src/data/site.js`). Switching pushes the other URL with `history.pushState` and updates `<html lang>` and the title; the choice is also saved in `localStorage["lang"]`, which only serves to send a returning French visitor from `/` to `/fr` after mount. `t()` can also return arrays or objects. For example, `Experience.jsx` renders `t("experience")` (jobs with `org`, `role`, `date`, `points`), `t("education")` (degrees with `org`, `degree`, `note`) and `t("certification")`. Diplomas deliberately have no dates; only jobs do. Any user-facing text change has to be made in both the `en` and `fr` trees.
- **Projects:** `src/data/projects.js` holds the metadata: image import, link, `hosted`, `category` (`commercial` | `opensource` | `personal`), `tech`, and `descriptionKey`. The description text is at `portfolio.projects.<descriptionKey>` in both languages. `commercial` projects are shown twice: as the "live stores" links in the hero and as the bento cards at the top of `Portfolio.jsx`. Everything else goes in the card grid below, with `hosted` projects first (they link to the live site, e.g. CAFEA Espresso, whose repo is private) and then Magento projects; the rest link to GitHub. Every card opens `work/ProjectDetail.jsx`, a dialog whose image and title share a `layoutId` with the card (shared-element transition). Project images go in `src/assets/projects/`: 1200×630 WebP covers (rendered at 1600×840) that share one art direction with the site. They are generated, not hand-made: `scripts/covers/capture.js` screenshots the live client stores and this site (desktop + mobile), and `scripts/covers/render.js` builds every cover from HTML (real screenshots in a browser window + phone for client stores and the portfolio, UI mockups in the site palette for the open-source projects). Both need `npm i --no-save puppeteer-core`; add a new project's mockup to `COVERS` in `render.js`. The featured bento card is roughly square from `lg` up, so it uses an optional taller cover (`srcTall`, e.g. `carhartt-tall.webp`, 1200×1050) through `<picture>`.
- **Resume PDFs are the source of truth for content.** Experience bullets, client-store contributions and `SKILL_GROUPS` in `Skills.jsx` mirror the PDFs in `public/` (spoken languages come from `t("skills.spoken")`; brand icons for skills live in `components/skills/skillIcons.js`, an idle-loaded chunk, and `HAS_ICON` in `Skills.jsx` must list the same names so space is reserved). When the resumes change, update the site and `SYSTEM_PROMPT` to match. Contact and social URLs live in `src/data/contactLinks.js`.
- **Design system:** dark "futuristic, premium, calm" theme. All colors are semantic CSS variables in `src/index.css` (`--bg`, `--surface`, `--surface-2`, `--text`, `--muted`, `--border`, `--border-strong`, `--accent` #4CC9FF, `--accent-soft`, `--live`, `--danger`) mapped to Tailwind names in `tailwind.config.js` (`canvas`, `surface`, `fg`, `muted`, `line`, `accent`, `live`, `danger`), so a light theme only needs to redefine the variables. The cyan accent is used sparingly (the word "anything" in the hero, CTAs, focus rings, active states); green (`live`) is only for the live-store dot. Radii, shadows, the easing curve and the three durations (150/400/800 ms) are tokens too, mirrored for JS in `src/lib/motion.js`. Fonts: Geist 400/600 and Geist Mono 400, self-hosted in `public/fonts/` (subset to Latin + punctuation, preloaded, `@font-face` in `public/index.html`). The font-weight scale is replaced, so only `font-normal`/`font-semibold` exist. Shared classes (`.page`, `.section`, `.eyebrow`, `.section-title`, `.btn-primary`, `.btn-secondary`, `.text-link`, `.chip`, `.card`, `.spotlight`, `.grid-bg`) are in `src/index.css`. There is no logo mark, only the text wordmark.
- **Motion:** `motion` (`motion/react`) with `LazyMotion strict`, so components must use `m.*`, never `motion.*`; features (`domMax`) are passed synchronously (loading them async re-rendered the whole tree in one long task when they arrived). Primitives in `src/components/motion/`: `Reveal` (fade-up once), `SplitHeading` (word-masked title reveal), `ScrollText` (scroll-linked word opacity), `Magnetic` (CTAs); `usePointerCard` gives cards the cursor spotlight and tilt without re-rendering. Animate only `transform`/`opacity`. `MotionConfig reducedMotion="user"` plus the CSS reduced-motion block handle `prefers-reduced-motion`. Premium layer on top: `lib/smoothScroll.js` starts Lenis inertial scrolling on fine-pointer devices only, as a lazy chunk once the page is idle, and skips it with reduced motion. It honours `scroll-padding-top` for anchors, so give it no extra offset. It pauses while `body.overflow-hidden` (modals) is set and leaves `[role=dialog]`/`[data-lenis-prevent]` boxes to scroll natively. Use `scrollToTarget()` for programmatic scrolls. The nav hides on scroll-down (`useHideOnScroll`, translate only) and stays visible for keyboard focus. `RollText` is the hover text roll on CTAs (needs `group` on the button). `.hero-in` (CSS, `--d` delay) sequences the hero after the headline; the subline is left out because it can be the LCP element. Project images get a curtain + settle reveal and client cards a scroll parallax (`MediaImage` in `ProjectCard.jsx`), and `work/CursorPill.jsx` is the "Case study →" pill that replaces the cursor over cards (fine pointer only). Experience dots light up as the progress line reaches them. The footer has the giant gradient wordmark (`.footer-mark`) and the live Fès local time. On large screens (≥1024×640) it is a curtain: `<main>` (`.page-sheet`, opaque, rounded bottom) scrolls up off the footer, which is pinned underneath (`.footer-curtain`, sticky with `z-index: -1`). This only works because the App wrapper `<div>` is `isolate`, which keeps the footer clickable. The chat and resume modal live inside that wrapper so their z-indexes still rank against the nav and dialogs. The wordmark rise is driven by the reveal progress (`useFooterReveal`), not `whileInView`, since the pinned footer always counts as in view. The desktop nav has a shared-layout active pill (`layoutId="nav-active"`) and `RollText` labels. Switching language crossfades the page with the View Transitions API (`LanguageContext`, skipped with reduced motion). The email row in Contact has a copy button.
- **Hero visual ("the stack"):** `components/hero/HeroVisual.jsx` is pure CSS 3D plus inline SVG, with no WebGL and no extra chunk, so it paints with the first frame everywhere. It shows four glass slabs (data, api, commerce, interface; labels at `home.stack.*` in both languages) with a cyan request dot travelling down through them, lighting each layer as it passes. Each slab is a plate plus an `.hs-edge` face just below it (the thickness) and an `.hs-sheen` band whose position follows the pointer; nothing in it moves unless the visitor does. As the hero scrolls away the stack spreads (`--s`). Styles are the `.hs-*` rules in `src/index.css`. Every size is in `cqw` (`.hs-root` is a size container), and the spacing is one registered `@property --gap`, so the intro, the hover "open" state, the beam and the packet all follow it. Desktop only: pointer tilt (`--px`/`--py`, written once per frame) and an `is-open` class from a manual hit-test, because the copy column covers the visual and `:hover` never fires. Labels must be direct children of `.hs-layer` (a `preserve-3d` element) to counter-rotate toward the viewer; inside the flat `.hs-plate` they get flattened. They are hidden below `xl` (1280px), where they would run past the viewport edge. The request loop is the only autoplaying/looping animation on the page; keep it that way (the one-shot hero headline rise and the stack's assembly are CSS).
- **SEO and prerender:** `scripts/seo/prerender.js` runs after `react-scripts build`. It loads the app's source in Node (Babel with the CRA preset; image imports resolve through `build/asset-manifest.json`), renders `<App prerendered initialLang />` with `renderToString` once per language, and writes `build/index.html`, `build/fr/index.html`, `sitemap.xml` and `robots.txt`. Each page gets its own head: title and description (`seo.*` in the translations), canonical, hreflang, Open Graph/Twitter and one JSON-LD graph (`WebSite`, `ProfilePage`, `Person`, plus the non-client projects with Mehdi as author; client stores stay out). The canonical origin is `SITE_URL` in `src/data/site.js` and nowhere else: `www`, because Vercel redirects the bare domain to it. The script checks its output (one `<h1>` with the name, canonical, alt texts, JSON-LD, unique titles) and fails the build otherwise; `public/index.html` only holds dev-server fallbacks. The `<h1>` is the eyebrow ("Mehdi Aichouch · Fès, Morocco") plus the headline. `public/og-image.png` (1200×630, a screenshot of the hero) is the link-preview image, regenerate it if the hero changes noticeably; `public/mehdi-aichouch.jpg` is the portrait the `Person` schema points at. `vercel.json` uses the legacy `routes` array on purpose (it is the only way to return a real 404 status while the CRA preset is active, and it cannot be mixed with `redirects`/`headers`/`rewrites`): it redirects the old `mehdi-aichouch.vercel.app` host, sets cache and security headers, and after `handle: filesystem` answers every unknown URL with `public/404.html` and status 404, ahead of the preset's fallback to `index.html`. Manual steps (Search Console, Bing, profiles) are in `docs/SEO.md`.
- **Anything rendered on the first pass must be the same in Node and in the browser**, or hydration falls back to client rendering for that section. Read `window`, `matchMedia`, `localStorage` or the clock in an effect, not during render (see `LocalTime` in `Footer.jsx`, `CursorPill.jsx`, `ScrollText.jsx`). To check: build, serve `build/`, and look for React errors #418/#423/#425 in the console, with and without `prefers-reduced-motion`.
- **Logic in hooks and services:** components use hooks (`useContactForm`, `useChat`, `useScrolled`), and hooks call services for network I/O. The contact form sets `noValidate` and runs its own bilingual validation.
- **AI chat assistant:** `chatService.streamChatResponse` is an async generator that streams SSE from the OpenRouter chat-completions API, tries each free model in `MODELS` in order, moving to the next one on an HTTP error or an empty reply (`openrouter/free` is OpenRouter's router across whatever free models are up). Free models are often rate-limited upstream (429) and get retired without notice, so when the chat breaks, first check that the IDs in `MODELS` still exist. Fallback attempts are logged with `console.warn("[AI chat] ...")`. The assistant's knowledge of Mehdi comes entirely from the hardcoded `SYSTEM_PROMPT` in that file. **When projects, the timeline, or skills change, update `SYSTEM_PROMPT` too**, or the chatbot will give outdated answers. A rate-limit error comes back as the sentinel message `"rate_limit"`, which `useChat` detects.
- The chat panel (`components/chat/ChatPanel.jsx`, with the markdown renderer) and EmailJS are lazy-loaded; keep heavy, below-the-fold or on-demand code out of the main bundle.

## Testing notes

Tests are in `src/App.test.jsx` (Jest + Testing Library, rendering the full `<App />`). Test setup already handles these cases:
- `react-markdown` and `remark-gfm` are ESM-only, so the `jest.moduleNameMapper` in `package.json` points them to mocks in `src/__mocks__/`.
- `src/setupTests.js` mocks `matchMedia`, `IntersectionObserver` and `scrollIntoView`, and sets `MotionGlobalConfig.skipAnimations` (jsdom has no layout, so exit/layout animations would never settle). `jest.moduleNameMapper` maps `motion/react` to its CJS build (Jest 27 ignores package `exports`). It also clears `localStorage` and resets the URL to `/` after each test so the language doesn't carry over into the next test.
